The second release of SignalBridge. It adds Sigma rules for identity attacks, scored on public
attack logs I didn't write and compared with SigmaHQ's rules for the same attacks. It also
corrects the documentation and refreshes the evidence viewer.

## What's new since v0.1.0

- **Identity attack detections.** 13 Sigma rules: W1–W5 for Windows domain controller events
  (Kerberoasting, password spraying, NTLM-only spraying, disabled-account logons, Kerberos
  pre-authentication turned off) and E1–E8 for Microsoft Entra ID sign-in and audit logs
  (password spraying, MFA fatigue, device code sign-in, new MFA methods, Temporary Access Pass,
  app consent, app credentials, disabled-account sign-in). They were scored beside SigmaHQ's 10
  rules for the same attacks on 23 captures from Splunk's attack_data, pinned by SHA-256. CI
  re-scores them on every change. See [`detections/identity`](https://github.com/aman-agarwal6/signalbridge/blob/main/detections/identity/README.md).
- **Corrected documentation.** The README, evidence guide and lessons learned now link the
  stale-permission-check and lab-password records. The README and evidence guide state the
  identity results' limits, and the evidence guide notes that the September receipts cite
  revisions from the unpublished history.
- **Refreshed evidence viewer.** A new identity detections card reads its figures from the score
  report. The access walkthrough now shows the October 3 Wazuh run that archived all 24 records,
  plus the later ZAP, Keycloak and Shuffle runs. The September evaluation page is labeled as
  superseded by the October 48-scenario round. The regenerated pages were rescanned with
  axe-core.
- **Dependency patch.** certifi in the pinned Sigma tooling (`detections/requirements.txt`) moves
  from 2026.7.22 to 2026.10.19.

## Limits

- The identity rules ran on attack-lab captures through SQLite, not in a production SIEM. Zero
  alerts on other files is a misfire check, not a false-positive rate.
- E8 and SigmaHQ's sign-in-to-disabled-account rule have no public capture to catch.
- I wrote down which rules should fire on each file before the first scoring run for W1–W4 and
  E1–E8. I added W5 after that run and set its expectations after seeing the results.
- Three SigmaHQ Entra rules can't fire on these captures' export format. I didn't test them
  through a SIEM's field mapping.
- Synthetic data in an isolated lab on one PC. This is not a production deployment.
- I wrote both the access-lab rules and their scenarios, so those scores catch regressions rather
  than measure real-world accuracy.
- The full 24-hour run was not completed.

The archive is built from this tag's commit by GitHub Actions, after the core and Sigma checks
passed on that same commit. It is signed with Sigstore build provenance. The SBOM is GitHub's
dependency graph for that commit.

```bash
gh release download v0.2.0 --repo aman-agarwal6/signalbridge
sha256sum -c SHA256SUMS
gh attestation verify signalbridge-v0.2.0.tar.gz --repo aman-agarwal6/signalbridge
```
