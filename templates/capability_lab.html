Safety boundaries

No autonomous agent, executable attack payload or real target is part of this lab.

Trusted fixed harness
  • Fresh in-memory database; the running console and original app databases are not test targets.
  • Network, DNS, listeners and child-process calls are blocked before scenarios run; the runner verifies those guards.
  • Fresh temporary signing keys; inherited app/cloud/database credentials and import preloads are excluded.
  • At most 750 in-process requests, 700 records per worker drain and a 120-second child timeout.
  • Evidence folders reject path redirection, and report files are created exclusively.

Python guards protect this fixed, reviewed code against accidental operations. They are not an operating-system sandbox for untrusted or hostile code. The separate Supabase service lab has its own lifecycle and isolation evidence.

Reproduce with the local operator tools

From the SignalBridge repository with its installed dependencies:

.venv\Scripts\python.exe -m unittest tests.test_simulation_safety
.venv\Scripts\python.exe scripts/run_enterprise_lab.py
.venv\Scripts\python.exe manage.py import_simulation --run-id RUN_ID --dry-run

Use the generated run ID. Review the result, then omit --dry-run to import it. No UI action launches a test or changes a source application.
